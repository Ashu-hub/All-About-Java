Core Concepts: Concurrency

1. Visibility Problems (volatile)

  • Multi-core CPUs use local caches → threads might miss the most recent updates to a variable!
  • Solution: The volatile keyword
  • Ensures updates are immediately written back to shared main memory.
  • Makes changes visible to ALL threads instantly.
  • Use Case: Simple flags or states where no complex logic is required.

2. Synchronization & Compound Ops (AtomicInteger)

  • Operations like value++ are NOT atomic!
  • They involve 3 steps: [READ] → [INCREMENT] → [WRITE]
  • Threads can interleave mid-process, causing lost updates.
⚠️ Warning: volatile does NOT fix this! It only handles visibility, not compound operations.

3. Solutions for Compound Operations

a) synchronized

  • Creates an exclusive lock.
  • Ensures one thread completes the entire block before another begins.

b) AtomicInteger (and AtomicReference)

  • Uses hardware-level instructions to perform compound ops atomically without explicit locks.
  • Key Methods: incrementAndGet(), addAndGet(), compareAndSet()

📌 Summary Recommendation

✔ Use volatile for basic visibility of simple flags.

✔ Use Atomic classes for counters or non-blocking algorithms requiring atomic compound updates.
